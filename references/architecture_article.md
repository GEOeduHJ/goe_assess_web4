# 지리과 AI 자동 채점 플랫폼 아키텍처 기술 문서

본 문서는 Streamlit 기반 지리과 자동 채점 플랫폼의 학술 논문 수록을 목적으로 (1) 개발 환경 및 활용 도구, (2) 플랫폼 아키텍처 및 주요 기능 설계, (3) 지리과 서답형 문항 유형별 채점 프롬프트 설계를 체계적으로 정리한다.

---
## 1. 개발 환경 및 활용 도구

### 1.1 개발 언어 및 런타임
- **언어**: Python 3.10 (pyproject.toml의 `requires-python >=3.10` 근거)
- **실행 프레임워크**: Streamlit (인터랙티브 웹 UI 및 세션 상태 관리)
- **모듈 구조**: 기능적 책임 분리를 기반으로 models / services / ui / utils 계층화

### 1.2 핵심 라이브러리 및 역할
| 범주 | 사용 라이브러리 | 역할 요약 |
|------|----------------|-----------|
| Web UI | `streamlit` | 다중 페이지 상태, 업로드 위젯, 인터랙티브 컴포넌트 |
| 데이터 처리 | `pandas`, `openpyxl` | Excel 파싱 및 구조화된 학생 답안 로딩 |
| 생성형 AI | `google-generativeai`, `openai` | LLM 기반 서술형 및 이미지(멀티모달) 채점 |
| RAG 및 임베딩 | `sentence-transformers`, `faiss-cpu`, `langchain-community` | 문서 분할, 임베딩 생성, 벡터 검색(선택적) |
| 문서 파싱 | `pypdf`, `python-docx` | PDF / DOCX 참고자료 텍스트 추출 |
| 시각화 | `plotly` | 결과 통계, 분포, 분석 대시보드 그래프 |
| 환경/설정 | `python-dotenv` | .env 기반 API 키 로딩 |
| 품질/테스트 | `pytest` | 단위 및 회귀 테스트 (dev 그룹) |

### 1.3 구성 / 설정 관리
- `config.py`에서 API 키, 임베딩 모델(`EMBEDDING_MODEL`), RAG 파라미터(문서당 청크 제한, Top-K), 재시도 정책(`MAX_RETRIES`), 배치 크기(`BATCH_PROCESSING_SIZE`)를 중앙관리.
- `.env`와 Streamlit `secrets` 양자 지원: 배포 환경별 분기 없는 이식성 확보.
- 설정 함수 `validate_available_api_keys()`는 Gemini / OpenAI 키 중 하나 이상이 있는지 확인하고, 선택 모델은 채점 시작 시 별도로 검증한다.

### 1.4 성능 및 운영 고려
- **배치 처리 최적화**: 대규모 학생 처리 시 `BATCH_PROCESSING_SIZE` 조정 가능.
- **재시도 및 Backoff**: 오류 유형별 재시도 정책과 지수 backoff 적용(네트워크/Rate Limit 견고성 향상).
- **온디맨드 RAG**: 참고 자료는 채점 직전 필요 시 처리 → 초기 로딩 지연 최소화.
- **캐시 전략(LLM)**: 동일 프롬프트 결과 재사용(구현부: `llm_service` 내부 캐시 딕셔너리).

### 1.5 품질 및 신뢰성
- 구조화된 오류 객체(`ErrorInfo`) 기반 일관된 사용자 메시지 + 기술 세부사항 expander 출력.
- 예측 불가능한 API 실패 대비: 모델 전환 및 실패 학생 재처리 UI 옵션 제공.

## 2. 플랫폼 아키텍처 및 주요 기능 설계

### 2.1 계층 구조 개요
```
┌─────────────────────────────────────┐
│            UI Layer (Streamlit)     │
│  main_ui / rubric_ui / grading_ui   │
└───────────────┬─────────────────────┘
                │ 세션 상태 (st.session_state)
┌───────────────▼─────────────────────┐
│          Service Layer              │
│ file_service | grading_engine |     │
│ llm_service  | rag_service          │
└───────────────┬─────────────────────┘
                │ 데이터 객체 교환
┌───────────────▼─────────────────────┐
│          Model Layer (dataclass)    │
│ Student | Rubric | GradingResult    │
└───────────────┬─────────────────────┘
                │ 유틸 호출
┌───────────────▼─────────────────────┐
│          Utils Layer                │
│ embedding_utils | error_handler     │
└─────────────────────────────────────┘
```

### 2.2 주요 페이지 기능 흐름
1. **채점 시스템 설정(Main)**: 문항 유형 선택 → LLM 모델 선택(Gemini 또는 GPT-5 Mini) → 파일 업로드(학생 답안/백지도 + 참고자료) → 전처리(`FileService`) → 세션 상태 저장
2. **평가 루브릭 입력(Rubric)**: 요소/기준 CRUD → 실시간 총점 계산 → 검증(중복 점수, 누락 필드) → JSON 내보내기/불러오기
3. **채점 실행(Grading)**: `SequentialGradingEngine` 구동 → 학생별 순차 채점 → 실시간 진행률/예상 완료시간 계산 → 오류 발생 시 복구 옵션
4. **결과 출력(Results)**: `GradingResult` 집계 → 통계/분포/개별 근거 피드백 시각화 → CSV/Excel 내보내기

### 2.3 세션 상태 설계
| 상태 키 | 용도 |
|---------|------|
| `grading_type` | 채점 유형(DESCRIPTIVE / MAP) |
| `selected_model` | LLM 엔진(gemini/gpt-5-mini) |
| `uploaded_files` | 원본 업로드 파일 참조 딕셔너리 |
| `processed_students` | 전처리 완료된 학생 리스트 |
| `rubric` / `rubric_data` | 루브릭 객체 및 직렬화 데이터 |
| `grading_session` | 실행 중 세션(학생 집합, 루브릭, 모델 정보) |
| `student_results` | 최종 채점 결과 목록 |
| `uploaded_reference_files` | 참고 자료 원본 (RAG 온디맨드) |

### 2.4 핵심 서비스 컴포넌트
| 서비스 | 기능 | 내부 전략 |
|--------|------|-----------|
| FileService | Excel/이미지 파싱, 학생 객체 생성 | 임시 파일 저장 후 정리, 이름 기반 매칭 |
| GradingEngine (`SequentialGradingEngine`) | 순차 채점 실행, 진행 추적, 재시도 | 진행 콜백, 처리시간 기반 ETA, 상태 리스트 유지 |
| LLMService | 모델 선택, 프롬프트 생성, 응답 파싱 | Gemini / GPT-5 Mini 분기, 캐싱 |
| RAGService | 참고 문서 온디맨드 처리 및 관련성 검색 | 전처리(청크 + 키워드), 유사도 기반 추출 |
| ErrorHandler | 오류 분류 및 메시지 생성 | Enum 기반 유형/심각도 매핑, 이력 보존 |

### 2.5 오류 및 복구 설계
- **유형 분류**: FILE_PROCESSING / API_COMMUNICATION / VALIDATION / NETWORK / RATE_LIMIT 등
- **복구 전략**: 지수 backoff, 다른 모델 재시도, 실패 학생만 재채점, 무시 후 진행
- **UI 피드백**: 최근 오류 패널(expander) + 기술 세부사항 토글

### 2.6 성능/확장 전략
| 목표 | 적용 전략 |
|------|-----------|
| 초기 로딩 최소화 | 참고자료 지연 처리 (온디맨드 RAG) |
| 처리량 향상 | 배치 크기 튜닝 + 캐시 |
| 메모리 안정성 | 임시 파일/디렉터리 정리 함수 (`cleanup_temp_directories`) |
| 모듈 확장 | 모델/서비스 계층 인터페이스 분리 |

### 2.7 데이터 흐름 요약
1. 업로드: Excel/이미지/문서 → 임시 저장 → 전처리 → `Student` 목록
2. 루브릭: UI 구성 → `Rubric` 객체화 → 세션/엔진 전달
3. 채점: 학생별 프롬프트 생성 → LLM 호출(Gemini 또는 GPT-5 Mini) → JSON 응답 파싱 → `GradingResult` 축적
4. RAG(조건부): 학생 답안 + 문서 청크 임베딩 유사도 평가 → 관련 청크 프롬프트 삽입
5. 결과: 누적 `GradingResult` → 통계 및 시각화 → 내보내기

## 3. 지리과 서답형 문항 유형별 채점 프롬프트 설계

### 3.1 설계 원칙
| 원칙 | 설명 |
|------|------|
| 구조화 | JSON 스키마 강제 → 안정적 파싱 및 결과 재현성 확보 |
| 근거 제시 | 각 평가 요소별 reasoning 포함 → 교사 검증 가능성 강화 |
| 루브릭 반영 | 루브릭 구조(요소명, 점수 범위)를 프롬프트에 명시 |
| 확장성 | RAG 삽입 블록 존재 시 문맥 자동 증강 |
| 안전성 | 온도/탑파라미터 제한(temperature=0.1)으로 일관성 강화 |

### 3.2 기본 프롬프트 골격
```
당신은 지리 교육 전문가입니다. 다음 루브릭을 사용하여 학생의 답안을 채점해주세요.

[루브릭 구조]
{루브릭 요소명, 점수, 기준 설명 목록}

[학생 정보]
- 이름: {student.name}
- 반: {student.class_number}

[학생 답안]
{student.answer}

{선택적: RAG 기반 참고 요약 블록}

출력은 반드시 다음 JSON 형식을 따르세요:
{
  "element_scores": [
    {"element_name": "요소명", "score": 점수, "reasoning": "채점 근거"}
  ],
  "feedback": "총괄 피드백",
  "improvement_suggestions": ["개선 제안1", "개선 제안2"]
}
```

### 3.3 루브릭 직렬화 규칙
- 요소 순서는 UI에서 정의된 순서 유지 → 결과 해석 일치성 확보
- 각 요소는 최고점 기준 내림차순 정렬된 기준 설명 요약 포함(LLM 판단 일관성 향상)
- 변환 함수: `_format_rubric_for_prompt(rubric)` (요소/점수 압축 문자열 생성)

### 3.4 RAG 참조 삽입 전략
| 단계 | 처리 내용 |
|------|-----------|
| 1 | 업로드 문서 텍스트 추출(PDF→pypdf, DOCX→python-docx) |
| 2 | 문서 → 문장/청크 분할 (`CHUNK_SIZE`, `CHUNK_OVERLAP`) |
| 3 | SentenceTransformer 임베딩 생성 및 정규화 |
| 4 | 학생 답안 임베딩과 코사인 유사도 계산 → Top-K 추출 (`TOP_K_RETRIEVAL`) |
| 5 | 관련 청크 축약/정규화 후 프롬프트 내 `{references}` 블록 삽입 |

### 3.5 오류/불일치 대응
| 발생 상황 | 대응 |
|-----------|------|
| 모델 JSON 형식 위반 | 재파싱 실패 시 재시도(Backoff) → 실패 학생 목록에 표시 |
| 빈 reasoning | 기본 문구 삽입("추후 교사 검토 필요") 및 검토 플래그 |
| RAG 실패(타임아웃/파싱) | references 블록 미삽입 후 채점 계속 |

### 3.6 멀티모달(백지도형) 변형 포인트
| 구성 요소 | 차이점 |
|-----------|--------|
| 입력 | 이미지(base64 또는 파일 핸들) + 학생 메타 |
| 모델 선택 | Gemini 또는 GPT-5 Mini 멀티모달 분석 |
| 프롬프트 추가 문구 | "이미지에 표시된 지명/경계/표시 정확성을 기준으로 평가" |
| RAG 사용 | 일반적으로 비활성 (지도 자체 정보 기반) |

### 3.7 예시 출력(JSON)
```json
{
  "element_scores": [
    {"element_name": "내용 정확성", "score": 5, "reasoning": "기후 요소와 regional differentiation을 모두 정확히 설명"},
    {"element_name": "설명의 질", "score": 3, "reasoning": "구조는 명확하나 사례 구체성이 다소 부족"}
  ],
  "feedback": "핵심 개념을 잘 이해하고 있으며 사례 보강 시 상위 수준 도달 가능",
  "improvement_suggestions": [
    "기후 요인별 구체적 수치(예: 강수량 변화)를 인용",
    "지역 비교 시 공통점/차이점을 표 형태로 정리"
  ]
}
```

### 3.8 재현성 확보 조치
- 프롬프트 버전 태깅(선택적으로 hidden field 추가 가능)
- 모델명 + 파라미터(temperature, top_p) 로그 보존
- 루브릭 해시(SHA-256) 생성하여 결과 내보내기 시 포함(루브릭 변경 추적)

## 4. 주요 페이지별 사용자 상호작용 및 내부 처리 절차

본 절은 플랫폼을 구성하는 네 개의 핵심 페이지(1) 채점 시스템 설정, (2) 평가 루브릭 입력, (3) 채점 실행, (4) 채점 결과 출력에 대해, 사용자가 수행할 수 있는 상호작용과 그에 연계된 내부 처리 로직을 학술 기술 관점에서 연속 서술형으로 정리한다. 각 단계는 Streamlit 세션 상태(`st.session_state`)를 매개로 유기적으로 연결되며, 상태 일관성과 재현성을 확보하기 위해 명시적 키 갱신 전략을 따른다.

### 4.1 채점 시스템 설정 페이지 (초기 환경 구성 및 데이터 수집)
첫 화면 상단에는 제목 ‘채점 시스템 설정’과 안내 문구가 배치되어 사용자가 즉시 목적을 이해할 수 있다. 중앙 영역의 두 개 선택 버튼 ‘📝 서술형 문항’과 ‘🗺️ 백지도형 문항’은 채점 흐름의 분기점을 명확히 하며, 선택 직후 현재 선택 결과가 성공 메시지로 시각화된다. 이어서 ‘🤖 LLM 모델 선택’ 라디오 그룹이 나타나 ‘Google Gemini 2.5 Flash’와 ‘OpenAI GPT-5 Mini’ 중 하나를 고르게 하여 성능·비용·멀티모달 여부에 대한 사용자의 판단을 지원한다. 그 아래 ‘📚 참고 자료 (선택사항)’ 구역은 ‘참고 자료 업로드’ 위젯을 제공하여 PDF와 DOCX 여러 파일을 동시에 추가할 수 있게 하고, 업로드가 완료되면 ‘✅ N개의 참고 자료가 업로드되었습니다.’ 메시지와 함께 ‘📋 업로드된 참고 자료 목록’ 확장 패널로 파일명·크기·타입을 즉시 검토할 수 있다. 이어지는 ‘📝 학생 답안 데이터’ 영역에서는 ‘학생 답안 Excel 파일’ 업로드 위젯과 ‘📋 필수 Excel 파일 형식’ 도움말 패널이 동반되어 ‘학생 이름’, ‘반’, ‘답안’ 열 구성을 명확히 안내한다. 백지도형을 선택한 경우에는 ‘학생 정보 Excel 파일’과 ‘백지도 이미지 파일들’ 위젯, 그리고 이미지 파일명 규칙(파일명에 학생 이름 포함)을 설명하는 도움말이 교체 표시된다. 모든 필수 입력이 충족되면 하단 ‘📋 루브릭 설정하기’ 버튼이 활성화되며(미충족 시 비활성 상태 + 도움말), 클릭 시 업로드된 자료는 내부적으로 임시 저장 및 기본 구조 검증을 거쳐 학생 목록이 준비되고 성공 메시지(예: ‘✅ X명의 학생 데이터를 성공적으로 처리했습니다.’)가 나타난다. 참고 자료는 이 단계에서 즉시 임베딩하지 않고 이후 채점 실행 시점에 필요할 때만 처리(온디맨드 RAG)하도록 보류되어 초기 대기 시간을 줄이고 자원 사용을 최적화한다.

### 4.2 평가 루브릭 입력 페이지 (동적 기준 설계 및 검증)
‘📋 평가 루브릭 설정’ 화면은 평가 구조를 시각적으로 조립하는 작업 공간이다. 상단에는 ‘🆕 새 루브릭’, ‘📁 샘플 로드’, ‘💾 루브릭 저장’, ‘📂 루브릭 불러오기’ 네 가지 관리 버튼이 나란히 배치되어 초기화·예시 불러오기·JSON 내보내기·JSON 재사용 흐름을 한 번에 제공한다. 그 아래 ‘📊 현재 평가 요소’ 구역에 각 요소는 ‘📋 요소명 (최대 N점)’ 형식의 확장 패널로 표시되며, 패널 내부에서 ‘평가 요소 이름’ 입력 필드와 다수의 ‘점수’ + ‘기준 설명’ 편집 블록을 즉각 수정할 수 있다. ‘➕ 채점 기준 추가’ 버튼은 요소별 세부 기준을 연속 확장할 수 있도록 하며, 삭제 아이콘 ‘🗑️’은 불필요한 기준을 신속히 제거한다. 사용자가 아직 어떤 요소도 추가하지 않았다면 안내 메시지(‘📝 아직 평가 요소가 없습니다…’)가 방해 최소화 스타일로 표시되어 다음 행동을 유도한다. 페이지 중단부 ‘➕ 새 평가 요소 추가’ 섹션은 전용 입력 폼과 ‘➕ 추가’ 버튼을 제공하여 중복 이름 방지 검사를 통과한 새 요소를 즉시 상단 목록에 반영한다. 하단 ‘👀 루브릭 미리보기’ 구역에서는 ‘평가 요소 수’, ‘총 만점’ 지표와 함께 ‘📋 상세 루브릭 미리보기’ 확장 패널을 통해 요소별 점수 기준이 고득점→저득점 순으로 정렬된 목록 형태로 노출되어 점수 구간의 균형·중복 여부를 정성적으로 판단하게 한다. 검증 실패 시 ‘❌ 루브릭 검증 실패’ 메시지 아래 항목별 문제(예: ‘최소 1개의 평가 요소가 필요합니다.’, ‘중복된 점수가 있습니다.’)가 점 단위 리스트로 표시되며, 모든 문제가 해소되면 ‘✅ 루브릭이 올바르게 설정되었습니다!’ 상태로 전환된다. 마지막 ‘🚀 다음 단계’ 영역의 ‘✅ 루브릭 완료 및 채점 준비’ 버튼은 검증 통과 시 활성화되고, 클릭 즉시 성공 메시지와 함께 채점 실행 화면으로 이동한다. 이를 통해 사용자는 내부 데이터 구조를 몰라도 화면에 제공된 명칭과 시각 피드백만으로 평가 기준을 완성·확정할 수 있다.

### 4.3 채점 실행 페이지 (프롬프트 생성 · 순차 처리 · 오류 복구)
‘🚀 채점 실행’ 화면은 진행 제어와 상태 모니터링이 결합된 운영 대시보드다. 상단 정보 블록은 ‘총 학생 수’, ‘평가 요소 수’, ‘선택된 모델’과 같이 사용자가 직관적으로 해석 가능한 지표를 보여주고, 채점이 시작되면 ‘완료된 학생’, ‘실패한 학생’, ‘평균 소요시간’, ‘예상 완료시간’이 갱신된다. 중앙 제어 영역에는 ‘🚀 채점 시작’ 버튼이 초기 진입점으로 배치되며, 실행 후에는 ‘⏸️ 현재 학생 후 정지’, ‘⏹️ 채점 중단’이 상태에 따라 조건부 활성화되어 중단·조기 종료 전략을 선택할 수 있다. 오류 상황이 누적되면 ‘⚠️ 최근 오류’ 패널이 열려 주요 실패 사례를 압축 표시하고, 하단 또는 인접 구역에는 ‘🔄 실패한 학생만 재시도’, ‘🤖 다른 AI 모델로 재시도’, ‘⏭️ 오류 무시하고 계속’과 같은 복구 선택지가 나타나 네트워크 불안정·일시적 모델 응답 이상·형식 파싱 실패 등 비정상 상황을 사용자 결정 하에 완화한다. 서술형 채점에서 참고 자료를 업로드한 경우 별도 사전 처리 없이 채점 시점에 필요 부분만 추출·요약되어 프롬프트에 삽입되며, 이는 화면 상 사용자에게는 단지 “참고 자료를 포함해 보다 정밀한 근거를 도출했다”는 결과적 설명(요소별 근거 강화)으로 체감된다. 백지도형 모드에서는 업로드한 이미지가 자동 분석 대상이 되며, 별도의 텍스트 참고 블록이 없다는 점이 인터페이스 상 자연스럽게 드러난다. 전체 흐름 동안 사용자는 진행률 바와 요약 메트릭을 통해 작업 규모와 잔여 시간을 예측 가능하게 인지하고, 실패 복구 수단을 즉시 행사할 수 있는 제어적 주도권을 유지한다.

### 4.4 채점 결과 출력 페이지 (평가 산출물 분석 및 재현성 확보)
‘📊 채점 결과’ 페이지는 채점 완료 직후 축적된 데이터를 (1) 집단 수준 핵심 지표 요약(‘📈 전체 개요’), (2) 비교·선별 중심 카드 열람(‘ 전체 보기’ 내 ‘📋 학생별 결과 카드’), (3) 심층 개별 진단(‘👤 개별 결과’)의 3단 탐색 경로로 조직한다. 아래 서술은 실제 구현(UI 라벨·시각 요소 기준)과 계산 방식에 근거한 세부 기능 기술이다.

#### (1) ‘📈 전체 개요’ 영역
첫 진입 시 상단 ‘📈 전체 개요’ 블록이 표시되며 다섯 개 메트릭 카드가 한 줄(5열) 구성으로 렌더링된다.
1) ‘총 학생 수’: 결과 객체 개수 그대로(채점 성공 건 집계).
2) ‘평균 점수’: (모든 학생 총점의 평균)/(모든 학생 만점의 평균) 형식으로 “X.Y / M.N” 비율 문자열로 제시(백분율이 아닌 평균 실점 대비 평균 만점 구조라는 점이 강조됨).
3) ‘평균 채점시간’: 학생별 채점 소요 초(sec) 평균(소수 첫째 자리 반올림) 표시.
4) ‘총 채점시간’: 모든 채점 시간 합을 분/초로 가공(예: “3분 42초”).
5) ‘최다 등급’: 문자 등급(A/B/C/D/F) 출현 빈도 최빈값 + “등급” 접미로 표기.

등급 분포는 직후 2열 레이아웃 중 좌측에 파이 차트(Plotly 파이)로, 우측에 ‘등급별 학생 수’ 텍스트 목록으로 병렬 제공된다. 파이 차트는 등급별 고정 색상 팔레트(예: A=녹색, F=붉은색 계열)와 내부 퍼센트+라벨을 포함해 집단 성취 편중(상·하위 집중) 여부를 즉각적으로 시각화한다. 텍스트 목록은 A→F 순으로 존재하는 등급만 “등급: N명 (P%)” 형태로 출력되어 표본 수가 작아 파이 차트가 왜곡될 수 있는 상황에서도 정량 해석을 지원한다. 이 영역은 (i) 채점 파이프라인의 정상 완료 여부(학생 수·총 시간), (ii) 난이도 및 분포 안정성(최다 등급·파이 구조), (iii) 처리 효율(평균/총 시간)을 1차 점검하는 “운영 진단 + 성취 1차 스크리닝” 역할을 수행한다.

#### (2) ‘📊 전체 보기’의 ‘� 학생별 결과 카드’ 목록
보기 모드 라디오(“보기 모드 선택:”)에서 ‘📊 전체 보기’가 선택되면 상단에 세 개 컨트롤이 나란히 배치된다: (a) ‘정렬 기준’ 선택 상자(총점 순 / 백분율 순 / 이름 순 / 채점시간 순), (b) ‘정렬 순서’ 라디오(내림차순·오름차순), (c) ‘등급 필터’ 선택 상자(전체 또는 A/B/C/D/F). 사용자가 값을 변경하면 서버 재계산 없이 즉시 결과 리스트가 재정렬·필터링되어 탐색 반응성을 유지한다. 본문에는 ‘📋 학생별 결과 카드’ 그리드가 한 줄 최대 3개 열(Column)로 반복 구성되며, 전체 학생 수에 따라 행이 동적으로 확장된다.

각 카드 구성 요소는 다음과 같다.
1) 카드 배경 색: 등급별 파스텔 색상(A 녹/ B 청/ C 황/ D 연적/ F 적)으로 성취 수준을 사전주의 없이 직관 강조.
2) 헤더: “🎓 학생이름 (반)” 형식.
3) 상단 메트릭 2개: (i) ‘총점’ — “획득/만점” + delta로 해당 학생 백분율(XX.X%) 표시, (ii) ‘등급’ — 문자 등급 + delta로 채점 소요시간(초) 표시. 델타 활용을 통해 세부 값(백분율·시간)을 2차 정보로 겹겹 제공.
4) 평가 요소별 막대형 진행 표시: 각 요소에 대해 진행률 바(progress) 형태로 “요소명: 점수/만점 (백분율%)” 텍스트 병기(색상은 Streamlit 기본 진행률 바 스타일 활용).
5) ‘💬 피드백 보기’ 확장 영역: (i) 요소별 판단 근거(reasoning)가 존재하면 “판단 근거:” 접두로 요약 노출, (ii) 요소별 피드백이 있으면 “피드백:” 접두로 구분, 요소 간 구획선(—) 삽입 후, (iii) 전체 피드백(학생 종합 소감) 블록 표시.
6) 하단 정보 행: 좌측 ‘⏱️ 채점시간: X.Y초’, 우측 ‘📅 HH:MM:SS’(채점 완료 시각) 캡션.

이 카드 기반 ‘전체 보기’는 (a) 집단 내 상대 위치(성취·시간) 스캔, (b) 이상치(매우 짧거나 긴 채점시간·특정 등급 집중) 식별, (c) 세부 진입 전 선별(prioritization)이라는 3중 기능을 수행한다. 또한 피드백/근거를 카드 한 단계 아래(Expander)로 배치해 ‘정보 비용(Information Cost)’을 지연시키면서도 클릭 한 번으로 질적 판단을 확인하는 UX 균형을 제공한다.

#### (3) ‘👤 개별 결과’ 세부 보기
‘👤 개별 결과’ 모드 선택 시 상단에 학생 선택 상자(“학생 선택:”)가 표시되고, 선택 즉시 단일 학생 심층 패널이 렌더링된다. 상단 헤더는 “🎓 이름 (반)”과 함께 우측 2열 메트릭 ‘총점’, ‘등급’을 배치해 핵심 절대 성취를 즉시 파악 가능하게 한다. 이어지는 ‘📊 성과 요약’ 구역은 4개 메트릭(‘획득 점수’, ‘채점 소요시간’, ‘채점 완료시각’, ‘평균 요소 점수’)으로 구성되어 시간·요소 난이도·처리 안정성을 재확인한다.

‘📋 평가 요소별 상세 점수’ 구역은 (i) 요소별 획득점수 vs 만점 비교 막대 차트(이중 Bar)로 전반적 분포를 조망한 뒤, (ii) ‘📝 요소별 상세 정보’ 확장 리스트에서 첫 요소는 기본 확장 상태로, 각 요소 패널 내부에 게이지(반원 Gauge + Number + Delta)가 나타난다. 게이지는 0–100 축, 색상 구간(0–60: 회색 톤, 60–80: 중간, 80–100: 연녹)과 임계선(threshold=90, 붉은 선), Delta 기준(reference=80)을 활용해 목표 대비 초과/미달을 시각 부호화한다. 패널 우측 텍스트 컬럼에는 획득 점수·만점·백분율, (존재 시) 요소별 피드백이 구조화 문장으로 정리된다.

‘💬 전체 피드백’ 블록은 흰색 배경 + 좌측 강조선 스타일로 시각적 구획을 명확히 하여 교사가 종합 진단 메시지를 복사·이식하기 용이하다. 이어 ‘🎯 성과 분석 및 개선 제안’ 섹션이 나타나 자동 분류 로직을 기반으로 (a) 강점(80% 이상) 영역은 성공 메시지(녹색), (b) 개선 필요(60% 미만) 영역은 경고 메시지(황/주황), (c) 전체 평균 백분율 구간별 수준 진단(≥90 최우수 / ≥80 우수 / ≥70 양호 / ≥60 보통 / <60 개선 필요)을 단계적 이모지 + 컬러로 부여해 신속한 질적 해석을 지원한다. 이 계층적 피드백 구성은 교사가 재진단 없이 바로 재학습 전략(개선 영역 집중 지도)을 설계하도록 설계된 설명가능(Explainable) 출력 형태다.

마지막으로 페이지 하단 ‘📥 결과 내보내기’ 구역(세 보기 모드 공통)은 세 가지 버튼을 제공한다: (1) ‘📊 Excel 다운로드’ — 다중 시트(채점결과/평가요소별상세/요약통계/상세피드백)를 포함하는 통합 Excel 생성(시트별 컬럼 자동 너비 조정·결측 안전 처리), (2) ‘📈 분석 리포트 생성’ — 평균·중앙값·표준편차·등급 분포·시간 지표를 서술형 목록으로 즉시 출력, (3) ‘📋 요약 통계 보기’ — 표(DataFrame) 형태 요약 + (존재 시) 평가요소별 통계 표. 세부 산출물은 재현 연구(동일 루브릭·동일 모델 재실행), 후속 통계 분석(분산·상관·요인), 질적 피드백 아카이빙에 활용 가능하다.

요컨대 본 페이지는 ‘요약(Overview) → 선별(Selection) → 심층(Drill-down) → 내보내기(Externalization)’로 이어지는 평가 해석 활동 체인을 UI 구조에 매핑하여, 교사의 주의 자원 배분 효율과 결과 재현성·추적 가능성을 동시 달성하도록 구성되어 있다. (참고: ‘📈 분석 대시보드’ 모드는 추가 심층 통계·상관·시간 분석을 제공하나, 본 절 요구 범위(세 구획) 외 상세 기술은 생략하였다.)
