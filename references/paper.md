## 사용자 관점(UI 텍스트 기준)으로 정리한 플랫폼 설명

아래 내용은 실제로 사용자가 웹 브라우저에서 보는 문구와 흐름을 기준으로 정리한 설명입니다. 파일명·함수명 같은 내부 구현 정보는 최소화하고, 연구 논문에 포함하기 쉬운 가독성 높은 서술로 구성했습니다.


### 1) 첫 화면 — 채점 시스템 설정 (상세 보완)

이 섹션에서는 사용자가 처음 접속했을 때 마주하는 화면(제목: "채점 시스템 설정")의 UI 요소와 구체적 이용 흐름을 웹 텍스트(보이는 문구) 기준으로 상세히 기술한다. 목표는 연구 독자가 인터페이스만 보고도 사용성을 재현할 수 있게 하는 것이다.

- UI 헤더와 상태 요약
	- 페이지 상단에는 "채점 시스템 설정" 헤더와 요약 문구("AI 기반 지리과 자동 채점 시스템")가 표시되어 기능을 즉시 인지시킨다.
	- 사이드바에는 "🔧 현재 설정"(임베딩 모델, 배치 크기 등)과 "🔑 API 상태"(누락된 키 알림) 블록이 있어 운영 전 필수 조건을 확인하게 한다.
## 사용자 관점(UI 텍스트 기준)으로 정리한 플랫폼 설명

아래 내용은 실제로 사용자가 웹 브라우저에서 보는 문구와 흐름을 기준으로 정리한 설명이다. 내부 구현 세부(파일명·함수명)는 최소화하고, 논문 본문에 바로 활용할 수 있는 서술형 문장으로 재구성하였다.

### 1) 채점 시스템 설정

사용자가 애플리케이션에 접속하면 첫 화면에서 '채점 시스템 설정'이라는 제목 아래 모델 선택과 파일 업로드를 포함한 필수 입력을 순차적으로 수행하도록 유도한다. 초기 인터페이스는 직관적인 버튼(예: "📝 서술형 문항", "🗺️ 백지도형 문항")으로 채점 유형을 확정하게 하며, LLM 모델 선택(예: "Google Gemini 3.1 Flash Lite", "OpenAI GPT-5.4 Mini")을 통해 사용자가 성능·비용 트레이드오프를 고려하여 적절한 엔진을 지정할 수 있다. 문항 유형에 따라 동적으로 전개되는 업로드 위젯은 사용자가 요구 포맷(예: 학생 이름·반·답안을 포함하는 Excel 파일, PDF/DOCX 참고자료, 백지도 이미지)을 쉽게 확인하고 업로드할 수 있게 구성되어 있으며, 업로드 완료 시 즉각적인 성공·오류 메시지와 확장 패널을 통해 파일 세부 정보를 제공한다. 모든 필수 입력이 충족되면 '루브릭 설정하기' 버튼을 통해 다음 단계로 자연스럽게 이동하며, 서버 측에서는 업로드된 파일을 판독·검증하는 전처리 절차가 실행되어 문제 발생 시 사용자 친화적 오류 메시지를 반환한다.

### 2) 루브릭 설정

루브릭 설정 화면은 교사가 평가 기준을 정의하고 그 유효성을 검증할 수 있도록 설계되었다. 사용자는 '🆕 새 루브릭', '📁 샘플 로드', '💾 루브릭 저장', '📂 루브릭 불러오기'와 같은 관리 버튼을 통해 루브릭의 생성·재사용·수정을 손쉽게 수행할 수 있다. 각 평가 요소는 확장 가능한 패널 형태로 제공되며, 요소별 이름과 다수의 채점 기준(점수 및 설명)을 입력하면 우측의 '루브릭 미리보기'에서 실시간으로 총점과 요소 수가 갱신된다. 시스템은 기본적인 검증 규칙(예: 최소 1개 요소 필요, 기준 설명 미기재, 중복 점수 허용 금지)을 적용하여 사용자가 논리적으로 일관된 루브릭을 만들도록 유도하며, 검증을 통과하면 '✅ 루브릭 완료 및 채점 준비' 버튼으로 채점 단계에 진입한다. 이 과정은 자동화된 채점 결과의 타당성을 확보하기 위한 사전 장치로 기능한다.

### 3) 채점 실행

채점 실행 화면은 운영자가 배치 채점 과정을 통제하고 모니터링할 수 있도록 설계된 대시보드이다. 상단에 제시되는 요약 메트릭(총 학생 수, 선택 모델, 평가 요소 수 등)과 실시간 진행 지표(완료·실패 학생 수, 평균 소요시간, 예상 완료시간)는 내부적으로 각 학생의 처리 시간을 집계하여 동적으로 계산된다. 운영자는 '🚀 채점 시작' 버튼으로 채점 프로세스를 가동하고, 필요 시 '⏸️ 현재 학생 후 정지', '⏹️ 채점 중단' 같은 제어 기능을 통해 작업을 중단할 수 있다. 오류가 발생할 경우 대시보드는 '⚠️ 최근 오류' 패널을 통해 상세 원인을 제시하고 '🔄 실패한 학생만 재시도', '🤖 다른 AI 모델로 재시도', '⏭️ 오류 무시하고 계속'과 같은 복구 옵션을 제공하여 운영자가 신속하게 대응할 수 있도록 한다. 또한 서술형 채점에서 업로드된 참고자료는 필요시 RAG 절차를 통해 온디맨드로 검색·요약되어 프롬프트에 포함되며, 이는 채점의 근거 제시와 피드백의 질을 높이는 데 기여한다.

### 4) 결과 분석 및 내보내기

채점이 완료되면 결과 페이지에서 전체 요약과 개별 결과, 심층 분석을 제공한다. 전체 요약은 평균 점수, 평균 채점 시간, 등급 분포 등의 핵심 통계로 구성되며, 등급 분포는 시각적으로 파이 차트 등으로 제시되어 집단별 성취도 편차를 직관적으로 파악할 수 있게 한다. 개별 결과 모드는 각 학생에 대해 루브릭 요소별 점수와 LLM이 제시한 판단 근거 및 개선 피드백을 병기함으로써 인간 교사가 자동 채점 결과를 쉽게 검토하고 필요 시 조정할 수 있도록 한다. 분석 대시보드는 점수 분포 히스토그램, 요소별 평균 비교, 채점 시간 트렌드, 점수-시간 상관관계 등 연구적 분석에 적합한 시각화를 제공하며, 모든 결과는 CSV/Excel 형식으로 내보내어 재현성 확보를 위한 입력 데이터, 루브릭, RAG 요약, 가능한 로그 정보를 함께 보관할 수 있다.

### 결론 — UI 텍스트 중심의 설명 요약

본 문단들은 사용자가 웹 인터페이스에서 실제로 보는 버튼·라벨·알림 문구(예: "📝 서술형 문항", "참고 자료 업로드", "✅ 루브릭 완료 및 채점 준비", "🚀 채점 시작", "📊 채점 결과")를 기준으로 재구성되었다. 논문 본문에는 내부 파일명이나 함수명을 나열하기보다는 이와 같은 사용성 중심 서술을 채택할 때 독자가 시스템의 목적·구성·운영 절차를 보다 직관적으로 이해할 수 있다. 필요 시 각 UI 요소 옆에 간단한 기술 주석(예: 사용 가능한 모델, 요구 파일 형식, RAG 사용 여부)을 덧붙여 재현 가능성을 보완할 것을 권장한다。
